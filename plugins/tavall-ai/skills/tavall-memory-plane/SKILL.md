# Tavall Memory Plane

Use memory as context, never as a substitute for current source/runtime evidence. Select only the modes the task needs: **BOOTSTRAP**, **INVESTIGATION**, **WRITEBACK**, **REVIEW**, **VALIDATION**.

## Current execution plane

When current repository/runtime/deployment evidence matters, bootstrap/resume the Tavall DEVELOPMENT session through the connected Tavall surface. Use Tavall Console with normal `tavall`, `git`, `gh`, build, and shell commands for ordinary evidence/execution. Discover additional typed capabilities through the live Function Catalog instead of assuming a frozen client tool list.

Tavall Cloud owns execution/environment authority. Tavall memory providers keep their own data authority.

## Authority order

1. Current source/runtime/database evidence.
2. Canonical exact durable Tavall memory.
3. Verified structural/temporal evidence.
4. Semantic/prior-fix recall.
5. Prompt/thread history.
6. Model recollection.

Semantic similarity is a lead, not proof.

## BOOTSTRAP

Use `memoryContext` or its discovered equivalent once early with the narrowest useful project/repository/thread/query scope. Do not repeat cosmetic variants. Verify current source/runtime state before acting on recalled claims.

## INVESTIGATION

Use only the needed memory capabilities: prior fixes, related contexts, structural dependencies/blast radius, temporal history, and provider telemetry. Reconcile every conclusion against current evidence through the authorized Tavall execution surface.

## WRITEBACK

Use `recordMemory` or its discovered equivalent only for a verified reusable conclusion that improves future decisions. It is a promotion boundary, not transcript logging. Preserve the narrowest true scope and exact provenance such as commit/PR/environment evidence. Never persist credentials, raw chats, transient tool narration, unverified semantic matches, or unresolved hypotheses.

## REVIEW

Hydrate the task/PR scope, then independently read the exact current diff/source and validation evidence. Use memory for prior context and blast-radius/history support, not to avoid reviewing changed code.

## VALIDATION

Bind acceptance evidence to one exact commit/source snapshot. If the head changes, previous evidence becomes historical. Use repository-owned validation, current environment evidence, provider health, durability/restart checks, and `git diff --check` as applicable. For Tavall engineering policy/docs, use `tavall-engineering-policy` and selective current documentation lookup rather than recursive quality-document preloading.

If memory is unavailable, mark memory `DEGRADED` and continue only when current authoritative evidence is sufficient. Never claim memory bootstrap or writeback succeeded when the capability was absent.
